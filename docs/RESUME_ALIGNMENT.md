## 当前可用措辞

**产品目标与流程：** 面向有开发想法、但缺少需求判断依据的独立开发者，设计 GitHub 需求研究工具，将分散 Issue 整理为用户痛点、已有应对方式及带来源的机会卡，为开发选题提供依据。

**体验优化：** 针对输入阶段前置填写负担，设计由 Agent 生成研究理解与默认检索边界、用户确认并补充关键约束的交互流程，支持审核后恢复执行。

**质量迭代：** 针对无关来源混入和证据薄弱问题，结合领域相关性、项目成熟度及社区互动信号调整筛选排序；设计覆盖 4 个领域、20 条需求的分层评估方案，区分来源相关性、机会卡证据支持与异常流程处理。

如需恢复“提升至 100%”，应提供冻结的前后版本、相同测试输入、逐条人工标签、排序阶段、实际分子分母、零结果与失败数量；不得用来源仓库指标替换 Issue 指标。
